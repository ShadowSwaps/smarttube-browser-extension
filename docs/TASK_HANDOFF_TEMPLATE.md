# SmartTube task handoff

Use this selected-source brief for a substantial authorized task, repair, reviewer handoff or final return. Apply [WORKFLOW.md](WORKFLOW.md) and [REVIEW_POLICY.md](REVIEW_POLICY.md). Store filled records and findings privately under ignored `.investigation-tools/workflow/`; do not put personal browser evidence, credentials or full chat histories into public documents.

## Dispatch or repair brief

- Work-item ID, date, status, coordinator chat ID/title and exact owning task chat ID/title:
- Human authorization and limits (reference the actual request); allowed coordination and publication actions:
- Repository/branch, baseline commit, dirty paths and current candidate/tree identity:
- Intended result, preserved behavior, affected files/components, non-goals and stopping boundary:
- Selected source/evidence paths with commit or SHA-256 identities; prior failures and unresolved limits:
- Acceptance scenarios/commands, expected outcomes, environment/artifact identity and evidence destinations:
- Inherited mandatory review, security, integration, release and installation gates; deferred/unrequested work:
- Review path and impact reason; implementation author(s), reviewer identity/authorship, actual review method:
- Stable findings ledger path; cumulative pass count/repair rounds used, remaining budget, open/closed/disputed IDs; exact explicit human authorization and added bounded limit for any extension (coordinator cannot extend):
- Actual model/reasoning/speed (or explicitly unavailable), proposed model/reasoning/speed and reason; configured defaults/no override unless explicitly authorized; no claimed control change without evidence:
- Latest usage check/time, minimum remaining across usable windows including weekly, unavailable windows and 10%/4% decision if applicable:
- Writer reservation, stopped/idle state of any prior owner, next gate and exact next action/decision destination:

## Result and return record

- Status: implemented / self-checked / awaiting non-author review / repair pending / checkpointed / accepted / publication pending / closure eligible / archived. Do not collapse these states into complete:
- Exact final commit/tree, changed files, diff/evidence paths and artifact SHA-256 where applicable:
- Per check: exact source, scenario/command, outcome/exit, browser/environment/configuration, artifact identity, evidence path; reuse rationale or unrun reason:
- Coverage: implementation, fixture, live-site, normal-profile acceptance, partial, failed or unrun; relevant preserved historical failures:
- Self-review identity/method and actual non-author reviewer identity/authorship/method; final findings dispositions and cumulative budget:
- Authorized publication destination/action, performed result and verified remote/artifact identity; otherwise explicitly pending, unnecessary or unauthorized:
- Remaining scoped fixes/checks/required inputs; separate backlog or unrequested installation; exact next action, responsible chat and return condition:
- Current task idle/active confirmation and writer state; evidence saved before ownership transfer:
- Coordinator acceptance identity/evidence; closure eligibility and exact archive target; archive authorization, observed result/time and recoverable reference if actually archived:

The owning task remains responsible for scoped corrections and authorized release verification until resolved. Return to SmartTube Coordinator for final closure when those obligations are closed; a finished implementation turn alone is an intermediate handoff. The coordinator must verify the exact completed, idle chat and saved evidence before recoverable archive. Keep the coordinator open and preserve pending items when checkpointing.
