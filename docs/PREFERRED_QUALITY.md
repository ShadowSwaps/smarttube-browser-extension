# Preferred playback quality

The repaired 0.4.7 runtime passed separate non-author verification and coordinator acceptance on 18 October 2026 (two review passes, one repair round). The everyday-readiness audit also passed coordinator non-author review. Public release review and distribution verification remain pending; see [release instructions](RELEASE_0.4.7.md). Current source and ZIP identities are recorded in [replacement readiness](ENHANCER_REPLACEMENT.md).

In Settings, **Preferred quality** offers **Auto**, **Highest available**, and fixed resolutions from 144p to 4320p. Auto is the installation default. Choose Highest available to request the greatest resolution offered by each ordinary watch video. A fixed target chooses the highest available resolution at or below the target. If none qualifies, native quality stays unchanged. This does not force codecs, frame rates or Premium formats.

SmartTube tries for up to eight seconds, with at most four selection calls. It confirms both the native reported quality and decoded video height before reporting confirmation. An accepted call alone is not success. A slow stream may remain unconfirmed when the window closes; there is no continuous enforcement or media reload forcing.

Opening native player Settings by pointer or keyboard cancels quality correction for that video, including before startup is ready. Native manual choices then take precedence even if the saved preference changes. The preference applies again on another video or page reload. Choosing Auto releases a selection owned by SmartTube when no manual override has occurred; otherwise it leaves the native choice alone. Disabling enhancements uses the same release behavior. If the native API or current-video identity is temporarily unavailable, release stays pending for up to eight seconds and at most four native calls. Successful release ends retries; exhaustion reports that release was not confirmed, including in the popup while enhancements are disabled. Native manual interaction cancels pending intervention. Default Auto never creates a quality constraint.

The narrow MAIN-world [adapter](../extension/native-quality.js) uses watch-player capabilities observed on the live site. These are not a guaranteed public quality API. Missing methods, unavailable formats, loading/ad state and mismatched video identity cannot establish success. YouTube can change these capabilities; native Auto/manual control remains the fallback. No new permission, service, remote executable code or storage namespace is introduced; the existing local settings object stores one validated preference.

## Verification boundaries

Author verification uses real packaged-extension integration fixtures plus signed-out live YouTube in headless isolated Brave with only SmartTube and `--mute-audio`. Playback is preceded by measured native/media 5% and Normal 1×, with playing-event measurements. Controlled fixtures cover unavailable lower targets, unsupported methods, early native gestures and retry/deadline bounds; these are not live service claims. Live evidence covers effective quality rather than settings alone. Exact candidate, package, harness identities, failures and scenario results are retained under the private work item `preferred-quality-20261018`.

Personal-profile/account behavior, Chrome/Edge, every aspect ratio/layout, actual ad transitions and community-service behavior remain unverified by this increment. The accepted 0.4.6 audit and its historical failures remain separate evidence. This candidate does not authorize removing Enhancer.
