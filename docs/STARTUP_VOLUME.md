# Native startup and wheel controls

The native startup/volume work passed separate non-author review and coordinator verification on 18 October 2026, followed by exact-package isolated update, navigation and full-process restart acceptance. These behaviors are retained unchanged in the accepted 0.4.7 runtime. The earlier human-reported 0.4.5 same-entry update retained settings/queue; this is historical evidence, not 0.4.7 personal-profile acceptance. Personal-profile installation/account/other-extension behavior remains optional and unverified. Public release review and distribution verification are separate pending gates; see [0.4.7 release notes](RELEASE_0.4.7.md). Earlier failures and cumulative review counts remain preserved.

## Startup behavior

**Apply starting volume** and **Mouse-wheel playback controls** default on; **Starting volume(%)** defaults to 5. Explicit saved volume/wheel opt-outs remain respected. For positive startup volume, the native adapter sets and verifies native/media volume before deliberately unmuting YouTube’s player. A zero target does not request unmute. YouTube unmute can restore its previous audible volume. During that synchronous call, a temporary guard uses the platform media-mute accessor to keep sound muted while the verified target is reapplied. The temporary own property is removed in finally, then media is unmuted only at the verified target. Any pre-existing own muted-property descriptor, including a configurable data property, rejects deliberate unmute before mutation or a success shortcut; its descriptor and existing playback are preserved. Native slider state and media are checked; a native failure attempts to mute again. There is no persistent property interception. Browser-tab/site mute and Windows audio are not changed.

While SmartTube enhancements are enabled, each new/reloaded video starts at **Normal(1×)** through the native player. Legacy saved startup speed/applySpeed values remain stored but no longer select startup behavior; their editable Settings controls have been retired. Deliberate native/SmartTube speed choices apply to the current video. New video navigation or a document reload starts normally again. Same-video media replacement does not renew the startup budget or erase manual precedence. Global/tab pause of enhancements remains respected.

Volume and speed correction each last at most four seconds/four attempts, including failed or partial API mutations. Manual native volume/mute/speed gestures and SmartTube actions cancel their corresponding startup correction. A new video, a relevant enabled/volume preference change, or resumed enhancements can start the relevant new bounded window. Startup speed skips recognized advertisements; startup volume also covers attached ad media. Other controllers can briefly change a value before correction or change it after the window ends. These are startup preferences, **not continuous speed or sound limits**, and do not guarantee uninstrumented first-sound timing.

## Wheel feedback and native state

Over the player, **Alt+wheel** changes volume by 5 percentage points; **Alt+Shift+wheel** changes speed by 0.05×. Positive wheel volume deliberately unmutes. Successful speed changes show actual achieved rate, for example **Speed 1.55×**. Native limits apply: the signed-out live capability probe accepted 1.55× with matching native/media/menu state but capped requests above 2×. SmartTube respects the available native range within its own 0.25–3× bounds and shows the achieved rate with limit feedback. It does not silently apply a DOM-only faster rate with a stale native menu. A stored legacy requested speed is not falsely represented as applied.

Volume and speed share the existing readable transient notice. It clears the actual fixed masthead, follows the visible player/viewport intersection, works with the ST toolbar off, and ignores outside headers in native fullscreen. It takes no focus, intercepts no pointers, uses polite status announcement and hides after 1.2 seconds. Ordinary scrolling and Ctrl/Meta-wheel remain available; ads, editable fields and wheel opt-out exclude SmartTube wheel handling. Native controls remain usable.

## Bounded local integration and validation

The local native-volume.js MAIN-world adapter remains top-frame-only on the existing exact YouTube match. Separate fixed volume and speed DOM protocols validate version/correlation,current video/source,connected media,field types/ranges and allowed keys. Native volume/mute and playback-rate methods are the only site operations. Speed requests use verified native range/state and media readback; receipts carry no extension authority. The isolated controller verifies resulting media/available native slider state, and exposes no privileged page messaging, storage, navigation, evaluator or network operation. No new host permission or web-accessible bridge resource is introduced. Failure reports unapplied preferences without a media-only success fallback.

Fixtures deliberately separate native/media/slider/menu state so DOM-only changes cannot pass as native integration. Focused tests cover startup unmute/zero/opt-out/manual precedence, fixed1× despite legacy settings, native rate limits/failures, readable speed/volume alternation, clipping/cinema/native fullscreen, stale/forged requests, attempt/time bounds, navigation and actual isolated process restart. Accepted signed-out live validation verified selected native settings-menu values and 5% playback; separate Enhancer coexistence results remain historical transition evidence. Exact-package isolated acceptance does not establish personal-profile compatibility.

Every test-owned launch/restart is isolated headless Brave with **--mute-audio**. Personal profile data, accounts, tabs, other installed extensions, protections and Windows audio remain untouched. The stopped normal-profile UI/URL automation route stays stopped. Only human-reported installed version/state is available; installed source/in-memory digest and remaining personal-profile/restart acceptance remain unverified.
